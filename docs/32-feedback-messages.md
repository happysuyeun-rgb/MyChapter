이 문서는 **사용자에게 무엇을 어떤 방식으로 알려야 하는지**를 화면별로 정리한다.  
에러 원인·서버 코드 매핑은 `20-error-cases.md`가 기준이고, 여기서는 **피드백 방식과 문구**만 다룬다.

## 1. 어떤 방식을 쓸지 (선택 기준)

| 방식 | 컴포넌트 | 언제 쓰나 | 예 |
|------|----------|-----------|-----|
| **Toast** | `useToastStore().showToast` (`Toast.tsx`, 3초, 하단, 모든 모달 위 `z-[70]`) | 작업이 끝났고 **화면이 바뀌거나** 사용자가 계속 진행해도 되는 결과 알림. 막지 않는 실패 안내 | 「기록을 삭제했어요.」, 「순서를 저장하지 못했어요…」 |
| **Inline** | 화면/모달 안 `text-danger` 문구 | 입력 검증, 사용자가 **같은 화면에 머무르며 고쳐야 하는** 실패 | 「최소 10자 이상 작성해주세요.」 |
| **확인 창** | `Modal` + 버튼 2~3개 | **되돌릴 수 없거나**(삭제), **소모되거나**(Free 발행 1회), **작성 내용이 사라지는** 행동 직전 | 「이 책을 발행할까요?」 |
| **ErrorState** | `ErrorState(title, onRetry)` | 화면 전체 데이터 로드 실패. 반드시 **다시 시도** 버튼 + 가능하면 NavBar(뒤로) | 「원고를 불러오지 못했어요」 |
| **Paywall** | `usePaywallStore().showPaywall()` | Pro 전용 기능·Free 한도 도달 | Pro 표지, AI 다듬기 3회 소진 |

### 지켜야 할 규칙

1. **모달 뒤에 오류를 숨기지 않는다.** 모달 안에서 실패하면 오류 문구도 **모달 안**에 보여준다.
2. **로딩이 끝나지 않는 화면을 만들지 않는다.** 모든 로드 `Promise`에 `catch` → ErrorState 또는 안내.
3. **성공했는데 실패처럼 보이지 않게 한다.** 부가 작업(통계·배지·임시저장 삭제) 실패는 본 작업 성공을 뒤집지 않는다.
4. **조회 실패를 Free/권한 없음으로 위장하지 않는다.** (예: 책 수 조회 실패 → Paywall ✗, 안내 Toast ✓)
5. **버튼 연타 방지:** 저장·삭제·발행·결제 중에는 버튼 `disabled` + 「…중」 라벨.

### 문구 톤

- 존댓말 `-어요` 체. 기술 용어·영문 에러 코드 노출 금지.
- 성공: **「~했어요.」** (무엇이 됐는지 명사로) — 「책 설정을 저장했어요.」
- 실패: **「~하지 못했어요. 다시 시도해주세요.」** — 원인 추정이 확실할 때만 덧붙인다.
- 확인 창 제목: **「~할까요?」**, 본문에 **결과(무엇이 사라지거나 소모되는지)** 를 한 문장으로.
- 확인 창 버튼: 주 행동은 동사(「발행하기」「영구 삭제」), 취소는 「취소」 또는 「계속 편집」처럼 머무는 행동.

## 4. 확인 방법 (목업)

`VITE_DEV_BYPASS=true`, `VITE_MOCK_PLAN=free`로 로컬 실행 후:

- [ ] 최종 검수 → 「이 책 발행하기」 → 확인 창 → 취소 시 아무 일 없음
- [ ] 원고 편집에서 글자 수정 → 「취소」 → 확인 창 3버튼
- [ ] 원고 편집에서 수정 없이 「취소」 → 바로 미리보기
- [ ] 자유 기록 작성 → ✕ → 임시저장 후 나가기 → Toast
- [ ] 자유 기록 작성 → ✕ → 삭제 후 나가기 → 다시 들어가면 빈 화면
- [ ] 책 설정 → 저장 → Toast 「책 설정을 저장했어요.」
- [ ] Pro 표지 탭 → Paywall → 결제(목업) → Toast + 같은 표지 다시 탭 시 Paywall 안 뜸
