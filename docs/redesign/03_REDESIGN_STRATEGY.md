# 03. 리뉴얼 전략

> Phase 1 · 코드/API/스키마/결제/발행 로직 **변경 없음** (본 문서는 방향만)

---

## 1. 추천 리뉴얼 방향 (1안)

### **Editorial Book Desk 강화** — “나라는 사람의 한 권을 만드는 작업실”

기존 `10_DESIGN_SYSTEM`의 Paper × Botanical × Vintage × Editorial × AI를 **폐기하지 않고 선명하게** 만든다.

| 축 | 의미 |
|----|------|
| 작업실 | 홈 = 오늘 기록 + 책 준비도 데스크 |
| 서재 | 내 책(프로젝트) 커버 선반 |
| 원고대 | 기록·챕터·원고·표지·발행 단계 |
| PAGE | 동반자(캐릭터) — 내비 아이콘 대체 금지 |

**채택하지 않는 대안**

| 대안 | 기각 이유 |
|------|-----------|
| Wellness Journal (클로디형 캘린더 일기) | 출판 USP 약화, 경쟁 일기 앱과 동질화 |
| Content Store (밀리형 탐색·큐레이션) | 소비형 서재 — MY CHAPTER는 **창작·발행** |
| Fintech Minimal Paywall | 결제 UX만 참고, 비주얼 주제로 부적합 |

---

## 2. 선택 근거

1. **코드·토큰이 이미 Editorial** — 전면 리브랜딩 비용 대비 효과.  
2. **제품 결정과 정합** — 온보딩 → `/project/new`, readiness·발행 게이트.  
3. **유아이볼 교훈** — Empty+CTA·성공 다음행동·동의 분리는 가져오되, 일기/구독스토어 IA는 거부.  
4. **리스크 낮음** — 라우트·API 유지, UI 셸·카피·컴포넌트부터.

---

## 3. 핵심 사용자 여정 개선 방향

| 여정 | 현재 마찰 | 개선 방향 |
|------|-----------|-----------|
| 신규 → 첫 책 | 톤 분절 | 온보딩 카피·진행 표시를 “첫 권 만들기”로 통일 |
| 매일 기록 | mode 단계 김 | 홈에서 모드 단축 / 최근 모드 기억 |
| 준비도 → 제작 | 잠금 이유 약함 | Desk 위젯: 남은 기록·일수·다음 잠금 해제 |
| 제작 → 발행 | 단계 가시성 | 원고대 스테퍼(시각만, 로직 유지) |
| Pro | 설득 약함 | Free/Pro 대비 카드 (결제 API 불변) |

---

## 4. 보존 원칙 (하드)

- Supabase 스키마·Edge·Secret·결제·발행 RPC **불변**
- 기존 프로젝트/기록/발행물 URL·ID **유지**
- 라우트 path **가급적 유지** (IA 매핑은 alias/라벨 우선)
- 동의·약관 본문은 **법률 승인본** 전까지 `public/legal` 덮어쓰기 금지

---

## 5. 성공 지표 (정성·정량 초안)

- 신규: 온보딩→첫 책 완료율  
- 기존: 주간 기록 저장 횟수  
- 제작: readiness 도달 후 원고 진입율  
- 주관: “일기 앱이 아니라 책을 만든다” 인식 (설문)
