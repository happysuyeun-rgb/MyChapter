## D1 · 보관함 (L-06)

### 문제

- P-07에서 보관한 책은 서재·홈·활성 책 선택에서 사라지지만 **다시 꺼낼 경로가 없다.**
- DB 트리거 `023_enforce_free_project_limit`는 보관 여부와 무관하게 프로젝트 행 수로 Free 1권을 판단한다. 사용자가 "보관했으니 새 책을 만들 수 있다"고 오해할 수 있다.
- Free 사용자가 유일한 책을 보관하면 홈/서재가 "첫 번째 책 만들기" 빈 상태를 보여주지만 실제로는 생성이 막힌다.

### 정책 (1A 확정)

| 규칙 | 내용 |
|------|------|
| 슬롯 | 보관한 책도 Free 1권 슬롯에 포함 |
| 해제 | **영구 삭제**만 슬롯을 비운다 |
| 복원 | 플랜과 무관하게 언제나 가능 (슬롯 변화 없음) |
| 데이터 | 보관 중에도 기록·챕터·발행본은 그대로 유지 |
| 발행본 | 보관한 책의 발행본은 마이 > 완성한 책에서 계속 열람 가능 |
| DB | 마이그레이션 없음 (`projects.archived_at` 사용) |

### 진입

```text
서재(/library) 하단 "보관함 · N권 →" (N>0일 때만)
보관 후 빈 서재/빈 홈 → "보관함 열기"
→ /library/archived
```

### 화면 구성 `/library/archived`

AppLayout 안(탭바 유지, 서재 탭 활성).

1. **Masthead** — 좌측 `←` 서재로, 우측 없음
2. **제목 블록** — eyebrow `ARCHIVE` · H1 `보관함` · `N권 · 잠시 내려둔 책`
3. **Free 안내** (Free + N>0) — sage 좌측 rule 노트  
   `보관한 책도 Free 1권에 포함돼요. 새 책을 만들려면 보관한 책을 삭제하거나 Pro로 전환하세요.`
4. **목록** — 서재 카드와 같은 hairline 행 (작은 `Book_defualt` + 제목 오버레이)
   - eyebrow `보관 2026.11.04`
   - 제목(serif) · 책 유형 · `기록 N개`
   - 액션(텍스트 버튼 2개, 행 안 오른쪽 정렬 아님 — 본문 아래 한 줄)
     - `서재로 꺼내기` (sage, 주 액션)
     - `영구 삭제` (terracotta)
5. **빈 상태** — `보관한 책이 없어요` / `서재에서 잠시 내려둔 책이 여기에 모여요.` / 버튼 `서재로 돌아가기`

### 상호작용

| 액션 | 확인 | 성공 후 |
|------|------|---------|
| 서재로 꺼내기 | 없음 (되돌릴 수 있는 동작) | 목록에서 제거 + 인라인 안내 `서재로 꺼냈어요` · 해당 책을 활성 책으로 지정하지 않음 |
| 영구 삭제 | Modal + `책 삭제` 입력 (P-07과 동일 문구·규칙) | 목록에서 제거 · Free 슬롯 해제 |

실패 시 행 아래 terracotta 한 줄 오류, 재시도는 같은 버튼.

### 빈 서재 / 빈 홈 (보관만 남은 경우)

| 조건 | 표시 |
|------|------|
| 활성 책 0 · 보관 0 | 기존 빈 상태 (`첫 번째 책 만들기`) |
| 활성 책 0 · 보관 ≥1 | eyebrow `ARCHIVED` · `서재가 잠시 비어 있어요` · `보관한 책 N권이 있어요.\n다시 꺼내 이어 쓸 수 있어요.` · CTA `보관함 열기` |

### 활성 책 처리

- `getProjects`는 보관 제외 → 보관한 책이 활성이었다면 `useActiveProject`가 첫 번째 활성 책으로 대체한다 (기존 동작).
- 복원은 활성 책을 바꾸지 않는다. 사용자가 서재에서 선택한다.

## D2 · 책 작업실 단계 UX (P-06)

### 문제

- `+ 오늘 기록하기`가 항상 유일한 검은 CTA라서, 준비도를 채운 뒤에도 **다음 제작 단계가 화면의 주 행동이 아니다.**
- `원고` 단계는 챕터가 있어도 `대기`로 보인다 (active 상태 누락).
- 발행 후에도 `발행` 단계가 Final Review로 이동한다 (발행본 보기로 가야 함).
- 완료 시점(원고 확인, 최종 검수) 정보가 없다.

### 설계

**NEXT STEP 블록** (헤더 shelf-rail 바로 아래, 화면 유일한 Primary CTA)

| 상태 | eyebrow | 문구 | Primary CTA | Secondary |
|------|---------|------|-------------|-----------|
| 준비도 미충족 | `NEXT STEP` | `재료를 모으는 시간이에요` + 남은 기록/일수 | `+ 오늘 기록하기` → `/record/mode` | 없음 |
| 준비 완료 · 챕터 0 | `NEXT STEP · 02` | `챕터를 만들어볼까요` | `챕터 만들기` → `/book` | `+ 오늘 기록하기` (텍스트 링크) |
| 원고 미확인 | `NEXT STEP · 03` | `원고를 처음부터 읽어봐요` | `원고 확인하기` → `/book/manuscript` | 동일 |
| 표지 미선택 | `NEXT STEP · 04` | `표지를 골라주세요` | `표지 고르기` → `/book/cover` | 동일 |
| 최종 검수 미완료 | `NEXT STEP · 05` | `마지막으로 확인해주세요` | `최종 검수하기` → `/book/review` | 동일 |
| 검수 완료 · 미발행 | `NEXT STEP · 06` | `이제 발행할 수 있어요` | `발행하러 가기` → `/book/review` | 동일 |
| 발행됨 | `PUBLISHED · vN` | `이 책은 발행되었어요` | `발행본 보기` → `/publication/:id` | `+ 오늘 기록하기` |

- Primary는 기존 ink solid 버튼(`min-h-[48px]`).
- 다음 단계는 PRODUCTION 단계 목록과 **같은 계산**에서 도출한다 (첫 번째 `ready && state !== 'done'`).
- READINESS 섹션의 기존 `+ 오늘 기록하기` 버튼은 제거한다 (NEXT STEP으로 이동).

**PRODUCTION 단계 수정**

| 단계 | 변경 |
|------|------|
| 원고 | 챕터 ≥1 · 미확인 → `active` · `확인 필요` |
| 원고 / 최종 검수 | 완료 시 설명에 날짜: `11.03 원고 확인 완료` |
| 발행 | 발행됨 → 선택 시 `/publication/:id` |

변경 없음: 잠금 규칙, 단계 순서, `StepperVisual` 컴포넌트 계약.

## D3 · Final Review 목차 (B-09) · 단일 CTA (U-01)

### 문제

- 목차가 번호+제목뿐이라 **비어 있는 챕터**나 분량 편차를 발행 전에 알 수 없다.
- 순서를 바꾸려면 어디로 가야 하는지 안내가 없다 (`/book`에 재정렬 기능 존재).
- `최종 검수 완료 저장`과 `이 책 발행하기`가 동시에 보여 Primary가 2개다.
- 헤더·섹션이 Editorial Desk 이전 스타일.

### 설계

1. **Masthead** — 좌 `←` 표지(`/book/cover`) · eyebrow `FINAL REVIEW` · H1 `마지막으로 확인해주세요`
2. **표지** (StudioSection `COVER`) — 선택 템플릿 미리보기 + 제목/저자/챕터 수 + `표지 변경 →`
3. **목차** (StudioSection `CONTENTS` · meta `N장`)
   - 행: `01` · 제목(serif) · 보조줄 `기록 N개 · 약 1,200자`
   - 본문이 비어 있으면 보조줄 대신 terracotta `원고가 비어 있어요` + 행 탭 → 챕터 편집
   - 섹션 하단 텍스트 링크 `목차 순서 바꾸기 →` → `/book`
   - 분량은 `user_content ?? ai_content` 공백 제외 글자 수, 100자 단위 반올림
4. **발행 체크** (StudioSection `CHECKLIST`) — 표지 확인 / 목차 순서 확인 / 원고 최종 확인
   - 빈 챕터가 1개 이상이면 `원고 최종 확인` 비활성 + 안내 `비어 있는 챕터를 먼저 채워주세요`
5. **플랜 노트** — 기존 문구 유지 (sage 좌측 rule)
6. **발행 진행 / 실패** — 기존 U-04/U-06 상태 유지, 스타일만 정리
7. **단일 Primary CTA**
   - 검수 미저장 → `최종 검수 완료 저장`
   - 검수 저장됨 → `이 책 발행하기` / `Pro로 계속 발행하기`
   - 저장됨 상태에서만 `검수 다시 하기` 텍스트 링크

서버 가드(`REVIEW_REQUIRED`, `MANUSCRIPT_INCOMPLETE`, `COVER_MISMATCH`)는 그대로 최종 판정이다. 클라이언트 빈 챕터 표시는 안내용.

## D4 · AI 편집 플로우 · 한도 (R-06 / R-10) — 설계만

> 2026-11-04: 챕터 범위만 구현 (아래 "구현 범위"). 기록 편집본은 여전히 설계 단계.

### 플로우

```text
기록 상세(R-05) 또는 챕터 편집(B-04)
→ "PAGE에게 다듬기 맡기기" (secondary)
→ 남은 횟수 확인 (Free) → 0이면 G-01 Paywall
→ 편집 중 (스켈레톤 · 취소 가능)
→ R-06 AI 편집 결과
   ├─ 원문 / 편집본 토글 (기본: 편집본)
   ├─ 변경 요약 1~3줄 (PAGE 노트 톤)
   ├─ [이 버전 사용] Primary → user_content(챕터) 또는 편집본 필드(기록)에 저장
   ├─ [다시 다듬기] secondary → 한도 1회 추가 차감
   └─ [원문 유지] text → 저장 없이 닫기
```

원칙 (PD-008): 원본 기록은 절대 덮어쓰지 않는다. 기록 편집본은 별도 필드/버전으로 저장한다 (DB 설계 필요 — 이번 사이클 범위 밖).

### 한도 후보 (R-10)

| 안 | Free | Pro | 장점 | 위험 |
|----|------|-----|------|------|
| Q1 | 총 3회 | fair-use(월 100) | 첫 책 체험이 명확, 비용 예측 쉬움 | 첫 책 이후 Free 재방문 동기 약함 |
| Q2 | 월 3회 | fair-use(월 100) | 꾸준한 기록 습관과 맞물림 | 장기 Free 사용자 누적 비용 |
| Q3 | 첫 책 진행 중 5회 · 발행 후 0 | fair-use | 첫 책 완성(PD-009)에 집중 | 규칙 설명이 복잡 |

**확정 (2026-11-04, PD-017): Q2 월 3회.** 기록 습관(월 단위 AI 질문 10회와 같은 주기)과 일관되고, `ai_usage` 월 집계를 그대로 재사용한다. M-03 AI 사용량 화면에 `AI 편집` 행을 추가하는 것으로 노출한다.

남은 결정: Pro fair-use 수치, "다시 다듬기" 차감 여부, 기록 편집본 저장 구조.

### 구현 범위 (2026-11-04 · 챕터 먼저)

- **챕터 편집(B-04)만 구현.** 기록(R-05) 편집본은 별도 필드 DB 설계가 필요해 보류.
- Edge `edit-chapter` · migration `026`(`ai_feature`에 `ai_edit`) · `src/lib/api/aiEdit.ts` · `ChapterEditPage` PAGE EDIT 섹션 + 결과 Modal.
- [이 버전 사용하기]는 편집기 내용만 바꾸고, 기존 [편집 내용 저장하기]로 `chapters.user_content`에 저장한다 (원본 기록 불변).
- 한도: Free 월 3회(UTC 월 기준) · Pro 잠정 월 100회. 생성 실패는 차감하지 않고, **"다시 다듬기"는 1회 차감(잠정 기본값)**.

## 공통 디자인 규칙 (10_DESIGN_SYSTEM)

- hairline 구분 · serif 제목 · sage eyebrow · terracotta는 경고·파괴 동작에만.
